# Los Pollos Hermanos Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the backend half of Los Pollos Hermanos: the Supabase schema, RLS and functions, the `lib/core` pure modules, the models, and all 7 repositories, each with a Fake and a Supabase adapter. When this is done, the frontend can build every screen against `FAKE_DATA=true` and then switch to the real backend with no code changes.

**Architecture:** The Flutter app talks to Supabase directly, with no custom server. Money, Stock, Order Status and Role changes happen only inside `security definer` Postgres functions. RLS is on every table, and the `anon` role gets nothing. The repository interfaces in `lib/data` are the seam, and each has an in-memory Fake adapter and a Supabase adapter. sqflite holds the Cart plus an offline read cache.

**Tech Stack:** Flutter 3.50.1 / Dart 3.14, `supabase_flutter`, `sqflite` (+ `sqflite_common_ffi` for tests), Riverpod 3 with codegen, `freezed` + `json_serializable`, `uuid`, `connectivity_plus`, `mocktail`. The Supabase CLI runs through `npx supabase`, for `db push` against the hosted project; no Docker is needed.

**Spec:**
- `docs/PRD.md` (requirements FR-1..20, NFR-1..8)
- `docs/design/modules.md` (**the exact interfaces**; read it with every task)
- `docs/design/architecture.md` (database functions, tables, failure modes)
- `docs/GLOSSARY.md` (names)
- `docs/adr/0001..0004`

## Global Constraints

- App id `com.lospolloshermanos.app`. Deep link `com.lospolloshermanos.app://login-callback`.
- Money in Dart is `Money(int centavos)`, never `double`. In Postgres it's `numeric(10,2)`. Platform Fee is `round(subtotal * 0.02, 2)`. Shipping Fee defaults to `50.00` per Order, from the `settings` row.
- Tier thresholds: `purity < 80` Street, `< 99` Pharma, `>= 99` Blue Sky. Purity is `numeric(4,1)` between 0 and 100.
- Order Status: `paid → packed → shipped → delivered`, plus `cancelled`. Customers cancel only before `shipped`.
- Roles: `customer`, `pharmacist`, `admin`, and they're exclusive. Signup accepts only `customer` or `pharmacist`.
- Cards store brand, last4 and expiry only. A Card with last4 `0002` is declined by `place_order`.
- RLS is enabled on every `public` table. `anon` gets no grants on any table or view.
- The service-role key exists **only** in `env.test.json`, for integration tests and the seed tool. It must never appear in `lib/`.
- `env.json` and `env.test.json` are git-ignored.
- Names follow `docs/GLOSSARY.md`: Store (not shop), Product (not medicine), Variant, Order, Checkout, Order Item.
- Pages hold 20 items.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Two Customers buying the last unit at the same time** must result in exactly one Order, while the other gets `OUT_OF_STOCK`. Covered by a Task 11 test.
2. **Double-tapping "Place order", or retrying after a timeout,** must produce one Checkout. Covered by a Task 11 test (same `checkout_id` twice).
3. **A forged signup** with `role: 'admin'` in its metadata must produce a Customer. Covered by a Task 8 test.
4. **A Pharmacist editing another Store's Variant price or Stock through the raw API** must be refused. Covered by a Task 14 test.
5. **Rounding at a half centavo** (2% of ₱0.25 = ₱0.005) must round to ₱0.01 in both Dart and SQL. Covered by tests in Task 2 and Task 11.

### Task 11: place_order, cancel_order and the checkout adapter (money + stock)

**Files:**
- Create: `supabase/migrations/20261128000004_checkout.sql`. It defines:
  - `place_order(p_checkout_id uuid, p_items jsonb, p_address_id uuid, p_card_id uuid) returns uuid`, as `security definer` with `set search_path = public`. Behavior is per `docs/design/architecture.md` §3:
    - If `p_checkout_id` already exists for this caller, return it at once.
    - Raise `BANNED` if the caller is banned, and `EMPTY_CART` if there are no items.
    - Select the Variants `for update`, ordered by id to avoid deadlocks.
    - Raise `UNAVAILABLE:<id>` when a Variant is archived, its Product is hidden or archived, or its Store isn't approved or is banned. Raise `OUT_OF_STOCK:<id>` when `stock < qty`. Raise `CARD_DECLINED` when the Card's last4 is `0002`.
