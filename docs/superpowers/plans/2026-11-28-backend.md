# Los Pollos Hermanos Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the backend half of Los Pollos Hermanos: the Supabase schema, RLS and functions, the `lib/core` pure modules, the models, and all 7 repositories, each with a Fake and a Supabase adapter. When this is done, the frontend can build every screen against `FAKE_DATA=true` and then switch to the real backend with no code changes.

**Architecture:** A closed market with one seller, where the Admin is the owner (ADR 0005). The Flutter app talks to Supabase directly, with no custom server. Money, Stock, Order Status and bans change only inside `security definer` Postgres functions. RLS is on every table, and the `anon` role gets nothing. The repository interfaces in `lib/data` are the seam, and each has an in-memory Fake adapter and a Supabase adapter. sqflite holds the Cart plus an offline read cache.

**Tech Stack:** Flutter 3.50.1 / Dart 3.14, `supabase_flutter`, `sqflite` (+ `sqflite_common_ffi` for tests), Riverpod 3 with codegen, `freezed` + `json_serializable`, `uuid`, `connectivity_plus`, `mocktail`. The Supabase CLI runs through `npx supabase`, for `db push` against the hosted project; no Docker is needed.

**Spec:**

- `docs/technical/modules.md` (**the exact interfaces**; read it with every task)

## Global Constraints

- App id `com.lospolloshermanos.app`. Deep link `com.lospolloshermanos.app://login-callback`.
- Roles are `customer` and `admin` only. Signup always creates `customer`. Admins come only from the seed tool. A Pharmacist is a catalog record, not a User or a Role: no account, no login.
- `pharmacists` has `id`, `name`, `photo_url`, `specialty`, `archived`, `created_at`; `products.pharmacist_id` is required. Pharmacists are Archived, never deleted.
- The Cart is global and one checkout creates one Order, even when lines come from several pharmacists; `place_order` snapshots `pharmacist_name` onto each Order Item.
- Money in Dart is `Money(int centavos)`, never `double`. In Postgres it's `numeric(10,2)`. Order Total = Subtotal + Shipping Fee. **No platform fee.** Shipping Fee defaults to `50.00` per Order, from the `settings` row.
- Tier thresholds: `purity < 80` Street, `< 99` Pharma, `>= 99` Blue Sky. Purity is `numeric(4,1)` between 0 and 100. Low Stock means `stock <= 5`.
- Order Status: `paid → packed → shipped → delivered`, plus `cancelled`. The Admin advances one step at a time. Customers cancel only before `shipped`, the Admin before `delivered`.
- One checkout = one Order. The app generates `orders.id`, and `place_order` is idempotent on it.
- Cards store brand, last4 and expiry only. A Card with last4 `0002` is declined by `place_order`.
- RLS is enabled on every `public` table. `anon` gets no grants on any table or view.
- The service-role key exists **only** in `env.test.json`, for integration tests and the seed tool. It must never appear in `lib/`.
- `env.json` and `env.test.json` are git-ignored.
- Names follow `docs/GLOSSARY.md`: Product (not medicine), Variant, Order, Order Item, Archived (not hidden).
- Pages hold 20 items.
- Development and tests run on the Pixel 8 emulator. The release APK must also install and run on a **Samsung Galaxy Tab A7** (Android 12 at most, arm64). Don't use any API that needs Android 13+ without a fallback.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Two Customers buying the last unit at the same time** must result in exactly one Order, while the other gets `OUT_OF_STOCK`. Covered by a Task 11 test.
2. **Double-tapping "Place order", or retrying after a timeout,** must produce one Order. Covered by a Task 11 test (same `order_id` twice).
3. **A forged signup** with `role: 'admin'` in its metadata must produce a Customer. Covered by a Task 8 test.
4. **A Customer changing a Variant's price or Stock, or an Order's status, through the raw API** must be refused. Covered by tests in Task 9 and Task 11.
5. **A Variant archived or repriced while it sits in a Cart** must not be sold at the old price. Covered by tests in Task 10 and Task 11.
6. **A Customer reading or writing pharmacists through the raw API** must see only non-archived pharmacists and must be refused all writes; Admin pharmacist CRUD goes through `savePharmacist` / `setPharmacistArchived`. Covered by tests in Tasks 8, 9 and 14.
